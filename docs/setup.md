# Запуск и настройка

Три контейнера. `vharvest` читает шары Keenetic и пишет карточки в Postgres. `web` показывает каталог в локальной сети. Ollama стоит на компьютере, не в Compose: контейнеру нужен GPU этой машины.

Сайт не проксирует видео. Пути для плеера описаны в [README.md](../README.md).

## Запуск

Docker Desktop должен быть запущен. Ollama на этом компьютере слушает `0.0.0.0:11434`.

```powershell
docker compose up -d --build
```

Сайт на этом компьютере: `http://127.0.0.1:8080`. Команды скана и сброса ниже ходят сюда же: PowerShell не проверяет домашний сертификат.

Телефон в той же сети открывает `https://<IP-этого-ПК>:8443`. Порт задаёт `WEB_TLS_PORT`. Адрес компьютера записан в `TLS_HOSTS`. Если адрес сменился, поправьте `.env` и пересоздайте контейнер `web`: иначе имя в сертификате не совпадёт, и Chrome снова откажется ставить приложение.

Контейнер `web` сам выпускает сертификат. Открытая часть скачивается телефоном с `http://<IP-этого-ПК>:8080/ca.crt` и ставится как удостоверяющий центр. Ключ остаётся в папке `certs/` на компьютере. Пока телефон центру не доверяет, `https://...` показывает предупреждение, и установка приложения не предлагается. Кнопка «всё равно перейти» это не лечит.

Android: скачанный файл открыть и выбрать «Сертификат центра сертификации». Пункт лежит в настройках безопасности, в блоке про шифрование и учётные данные. Затем полностью закрыть Chrome, открыть `https://<IP>:8443` и в меню выбрать «Установить приложение».

Кнопка **«Открыть папку»** на телефоне рассчитана на [AndSMB](https://play.google.com/store/apps/details?id=lysesoft.andsmb) (Samba client): у него есть intent `VIEW` + `smb://` и параметр `remote_folder`, CX Проводник из браузера папку по smb не открывает. В `.env` задайте `SMB_CLIENT_HOST` тем же IP, что в AndSMB (часто `192.168.1.1` или `KEENETIC_IP`). Логин шары при первом открытии спрашивает сам AndSMB.

| Приложение | smb из каталога | Где взять |
| --- | --- | --- |
| AndSMB | да, по intent | Google Play |
| MiXplorer | да, `ACTION_OPEN_FOLDER` | [XDA](https://forum.xda-developers.com/t/app-2-2-mixplorer-v6-x-released-fully-featured-file-manager.1523691/), сборка web: `VITE_ANDROID_FOLDER_APP=mixplorer` |
| CX Проводник | нет, только вручную через «Сеть» | Google Play |

iPhone: открыть скачанный файл и установить профиль. Затем Настройки → Основные → Об этом устройстве → Доверие сертификатам и включить полное доверие для «Каталог фильмов». Сайт ставится через «Поделиться» → «На экран Домой».

Уже открытые страницы, список и постеры остаются на устройстве, если сервер временно не отвечает. Плейлист в этот запас не входит: кнопка «В плеер» каждый раз спрашивает сервер.

После правки страниц или службы можно пересобрать один контейнер. Остальные при этом не трогаются и уже должны работать. `web` — страницы, `vharvest` — обход шар и API.

```powershell
docker compose up -d --build --no-deps web
docker compose up -d --build --no-deps vharvest
```

Первый запуск сам начинает скан, если база пустая, есть карточки в статусе `pending` или у уверенных карточек ещё не спрошен Кинопоиск. Потом скан идёт каждую ночь в 03:00 по Москве. Повтор с этого компьютера:

```powershell
$token = ((Get-Content .env | Where-Object { $_ -like 'SCAN_TOKEN=*' }) -split '=', 2)[1]
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8080/api/scan -Headers @{ Authorization = "Bearer $token" }
```

Пока идёт разбор, шапка сайта показывает файл и счётчик. Повторный запуск не стартует второй проход.

Номер карточки виден в каталоге и на странице фильма: кнопка «Карточка N» копирует его. Сброс очищает эти карточки и собирает их заново, без обхода шар. Пока идёт скан или другой сброс, команда отвечает отказом.

Та же форма открывается в браузере: на этом компьютере `http://127.0.0.1:8080/service`, на телефоне `https://<IP-этого-ПК>:8443/service`. Пароль — `SCAN_TOKEN`. Сайт держит его только в этой вкладке и не записывает на сервер.

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8080/api/movies/reset -Headers @{ Authorization = "Bearer $token" } -ContentType "application/json" -Body '{"ids":[1,2]}'
```

За один сброс — не больше 100 номеров.

## Что лежит в `.env`

Рабочий файл не коммитится. Образец полей — `.env.example`.

- `TMDB_API_KEY`, `KP_API_KEY` — карточка, постер, жанры, актёры и рейтинг Кинопоиска.
- `SMB_LOGIN`, `SMB_PASSWORD` — чтение шар. Пароль без запятой: запятая ломает параметры монтирования.
- `KEENETIC_IP` — адрес `Keenetic-1601`, с него монтируются `ADATA SC610` и `KINGSTON`.
- `SMB_HOST` — имя хоста в путях `\\хост\шара` для Windows. По умолчанию `Keenetic-1601`.
- `SMB_CLIENT_HOST` — хост только в `smb://` для телефона и macOS. Если не задан, берётся `SMB_HOST`. Для CX Проводника обычно IP роутера, как в закладке «Сеть» (например `192.168.1.1`).
- `SCAN_TOKEN` — пароль команд скана и сброса.
- `SCAN_CRON` — расписание ночного скана, по умолчанию `0 3 * * *`, часовой пояс Москва.
- `OLLAMA_MODEL` — модель, которая вытаскивает название из имени файла. Адрес Ollama для контейнера задан в `docker-compose.yml`: `http://host.docker.internal:11434`.
- `MIN_FILE_BYTES` — файлы меньше этого размера пропускаются. По умолчанию 50 МБ.
- `WEB_PORT` — порт сайта на этом компьютере, по умолчанию `8080`. По нему же ходят команды скана.
- `WEB_TLS_PORT` — порт HTTPS для телефона, по умолчанию `8443`.
- `TLS_HOSTS` — адрес этого компьютера в сети. Несколько адресов пишутся через запятую. Имя компьютера, если телефон открывает сайт по имени, пишется в `TLS_DNS_NAME`.

Служебные папки торрент-клиента (`blocklists`, `resume`, `torrents`, `watch`) и скрытые каталоги пропускаются. Файлы меньше `MIN_FILE_BYTES` тоже. Папка `download` сканируется вместе с остальными, включая вложенные каталоги. Берутся `mkv`, `mp4`, `avi`, `mov`, `m4v`, `wmv` и `ts`. Звуковые дорожки `.ac3` рядом с фильмом в каталог не попадают. Файлы `sample` и короткие имена с `trailer` пропускаются.

Если шара не смонтировалась, смотрите `docker compose logs vharvest` и сообщение `docker compose up`. После смены пароля SMB пересоздайте только тома шар:

```powershell
docker compose down
docker volume rm video_catalog_adata video_catalog_kingston
docker compose up -d
```

`docker compose down -v` удалит ещё и базу с постерами.

## Разработка страниц на этом компьютере

Страницы крутятся через Vite, API и база остаются в Docker. Контейнер `web` для этого не нужен: Vite проксирует `/api/` на `vharvest` по `http://127.0.0.1:8000`.

Сначала поднимите службу и Postgres. Потом один раз установите зависимости и запустите dev-сервер:

```powershell
docker compose up -d postgres vharvest
cd web
npm ci
npm run dev:docker
```

Каталог откройте в браузере по адресу, который напечатает Vite (обычно `http://127.0.0.1:5173`). Если API слушает не на `127.0.0.1:8000`, задайте другой адрес в `web/.env.local`: `VITE_DEV_API_PROXY=http://127.0.0.1:8080` — тогда запросы пойдут через уже поднятый контейнер `web`.

## Проверки кода

Зависимости службы — `vharvest/requirements.txt`. Из каталога `vharvest`:

```powershell
python -m unittest discover -s tests
```

Тесты не ходят в шары, Postgres и внешние API.
